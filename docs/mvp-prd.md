# piwork 桌面客户端 MVP 需求文档

> 2026-11-04：开发执行范围和任务状态以[精简开发计划](development-plan.md)为准。本地可用版优先完成办公主流程；账号登录、历史同步及 Web 续接仍为完整 MVP 需求，相关接口按此前决定暂缓。SQLite 迁移和完整备份恢复不阻塞首版本地闭环。

- 版本：V0.3，需求草案
- 日期：2026-11-03
- 产品定位：piwork 的桌面版本，面向办公人员；整体功能、命名与交互风格基本与 piwork Web 保持一致，并适配本地文件及桌面能力，编程是可支持的任务类型之一
- 参考范围：piwork Web、pi-gui、pi-pocket 的当前本地代码；本文的客户端功能为产品需求，不表示已实现。
- 平台：首发 macOS Apple Silicon（arm64），不发布 Intel 版本；界面语言简体中文、英文。最低目标系统为 macOS 13，不支持 Intel；实际可运行范围和安装升级仍需目标设备验收。

## 1. 产品目标与范围

让用户选择本地文件夹、配置模型网关并可登录 piwork 账号，通过对话完成资料整理、文档和表格处理等任务，在同一窗口查看输出，管理技能、MCP 和定时任务。

核心闭环：配置网关或登录 → 创建项目并选择目录 → 选择模型和技能 → 提交任务 → 查看执行进度 → 预览并打开成果 → 继续对话修改。

MVP 覆盖对话及成果预览、本地项目、账号和模型、技能/MCP、定时任务、系统设置，以及最小的权限、错误提示和运行历史。P0 为上线必备；P1 在 P0 稳定后纳入本版本，时间不足可延后。下文列为后续的能力不作为上线验收条件。

### 目标用户与场景

- 办公人员：整理会议资料、生成纪要和汇报材料。
- 项目负责人：以本地文件夹为项目资料，持续处理报告与表格。
- 用户在本机配置技能与 MCP；登录后可使用平台模型与基础历史同步。

### 成功指标（上线后衡量，非技术保证）

- 新用户首次完成登录、选择目录并发送任务的成功率 ≥ 90%。
- 预定义的文档整理、表格分析、报告生成各 10 次试运行中，至少 8 次产生可打开成果，人工检查结果记录原因。
- 已触发定时任务均能在历史中看到成功、失败或跳过原因；不允许无记录地丢失触发结果。

## 2. 信息架构与页面

| 入口 | 页面 / 区域 | 主要内容 |
| --- | --- | --- |
| 登录 | 登录页、服务地址配置 | Web 账号登录、连接状态 |
| 首页 | 项目空间、最近任务 | 创建项目、继续任务 |
| 对话 | 左侧导航 + 中间对话 + 右侧工作区 | 消息、工具进度、文件/成果预览 |
| 项目 | 项目详情 | 目录、任务、资料和产出 |
| 能力 | 技能、MCP | 列表、状态、权限、管理 |
| 定时任务 | 列表、编辑、历史 | 计划、执行状态、触发记录 |
| 设置 | 外观、语言、账号、连接 | 明暗模式、系统语言、登出 |

主窗口默认三栏；左侧可收起，右侧支持展开、收起与调整宽度。窄窗口下优先保留对话，预览以可切换面板展示。应用重启后恢复用户选择的布局及最近项目；不可用的文件提示重新定位。

## 3. 功能需求

### 3.1 对话任务处理与右侧预览（P0）

- 创建、切换、重命名、删除任务；项目任务显示所属项目。删除任务需确认，默认仅移除任务记录，不删除项目文件。
- 输入文本，拖入或选择本地文件/图片；显示文件名、类型、大小和上传或读取状态。用户可移除待发送附件。附件大小和类型按服务端限制或客户端配置提示，不能静默截断。
- 选择当前网关可用且当前账号有权使用的模型；发送后展示用户消息、流式回复、工具名称与执行状态；长输出折叠，失败可展开查看可读原因。
- 提供停止、重新发送失败消息、复制回复；同一任务运行中可停止，额外输入首版作为下一条消息，运行结束后由用户发送，不默认为打断指令。
- 列出本轮生成或修改的文件，标识名称、路径、状态；点击在右侧预览，支持在系统默认应用打开、定位文件、另存为。文件不存在或无权限时提示原因。
- P0 只读预览：纯文本、Markdown、常见代码文件、图片、PDF，以及 DOCX、XLSX、PPTX 的基本内容。DOCX 支持段落、常见字体样式、表格和图片；XLSX 支持工作表切换、单元格内容和基本数字格式；PPTX 支持逐页浏览、文字和图片。复杂图表、动画、特殊字体和公式重算不保证还原。旧版 DOC/XLS/PPT、加密、损坏或不支持的文件展示原因并提供系统打开。
- 候选组件：DOCX 评估 [docx-preview](https://github.com/VolodymyrBaydalka/docxjs)；XLSX 评估 [SheetJS CE](https://docs.sheetjs.com/docs/api/utilities/html/)（主要面向数据和数字格式，单元格样式支持有限）；PPTX 评估 [PPTXjs](https://github.com/meshesha/PPTXjs)。均为候选，须先核验许可证、维护与安全状态、Electron 兼容和样例保真度；不能满足时更换组件。渲染在隔离的只读界面，禁用文档脚本及宏。
- 预览目录内文件时展示名称和完整路径；外部附件标记来源。处理中文、空文件、大文件和不支持格式，过大时提示并支持系统打开。
- 网络中断时保留已输入草稿与已收到内容，展示连接状态；恢复后刷新任务最终状态。是否能续传以实际后端能力为准，不能宣称中断的运行必然恢复。
- 任务进程结束、失败或需要用户操作时显示状态；P1 可提供系统通知，并在设置中关闭。

验收：选择项目内文件并提交“整理成 Markdown 摘要”，消息流和工具状态可见，成果可在右侧预览并通过系统打开；断网、文件丢失、用户停止各有明确状态；删除任务不删除本地文件。

### 3.2 项目空间与本地文件夹（P0）

- 创建项目：对齐 Web 项目页弹窗——填写名称并在「源文件夹」区通过系统目录选择器添加一个或多个本地文件夹（支持多选），第一个即主文件夹；显示规范化绝对路径和访问状态。
- 项目可绑定多个源文件夹，其中一个为主文件夹：所有源文件夹可读取（列出、搜索、预览、作为附件），`project_write`/`project_create_office` 仅允许写入主文件夹，主文件夹也是 Agent 命令的默认工作目录。工具路径以 `源文件夹名/相对路径` 表示，裸相对路径解析到主文件夹。
- 项目主页对齐 Web `/projects/[id]`：居中内容列、头部（更多操作：编辑项目/移除项目）、胶囊输入框在项目内新建聊天、「聊天/来源」分段标签、聊天列表与来源（源文件夹）管理（设为主要、在访达中显示、移除、添加文件夹）。
- 重命名、编辑源文件夹集合与主文件夹、从列表移除项目（编辑弹窗内含「移除本地项目」）；移除前明确说明保留磁盘文件。已有任务保留创建时的文件夹路径快照，改动文件夹集不迁移历史文件。
- 目录不存在、移动、权限失效时标记不可用；任一路径已属于其他项目时拒绝并提示返回已有项目。
- Agent 默认只获得当前任务授权的项目源文件夹和用户明确添加的附件；访问其他位置或覆盖已有文件时展示操作目标与确认，实施时结合执行环境真实能力落实。
- 同一目录多任务可并行阅读；写入冲突需提示或串行化，不能将一个任务的输出静默覆盖为另一个任务的成果。

验收：创建并重启后恢复项目；移动目录后显示不可用并能重新绑定；移除项目后磁盘文件仍存在。

### 3.3 账号、自定义网关与模型（P0）

- 支持两种明确选择的连接模式：piwork 账号网关，以及用户配置的自定义网关。允许不登录使用自定义网关；登录入口始终可用。切换连接模式时显示当前模型来源，不自动切换请求目标。
- 账号网关：配置 piwork 服务地址并使用 Web 账号登录；服务端鉴权、返回有权限的模型，执行额度和用量限制并记录用量。额度不足、无权限、网络失败分别提示。提供登录续期与登出；服务商密钥只在服务端。
- 自定义网关：配置名称、Base URL、协议类型、API Key（可选）、模型 ID 和显示名称；支持测试连接、编辑、删除和设置默认项。MVP 先支持 OpenAI 兼容 API，模型列表发现失败时允许手动填写 ID；其他协议后续增加。密钥放系统安全存储，界面和日志不显示明文。
- 未登录时客户端不实施 piwork 账号额度限制；自定义网关自身的限额和计费由其服务提供方决定，客户端应展示其返回的错误。登录后，使用 piwork 账号网关时以服务端权限与额度为准；自定义网关的请求是否也受平台配额约束，取决于是否经过平台网关，不能在客户端宣称可约束直连外部服务。
- 同一任务固定网关及模型，切换前明确提示；模型请求不静默回退。退出账号清除设备令牌，保留用户明确配置的独立自定义网关。
- 本地任务内容、工具结果和必要的附件数据会发送至所选模型服务；配置界面明确显示目的地址。离线可浏览已缓存记录，联网模型调用显示不可用。

账号登录、模型代理、额度和历史同步保留为产品需求；设备认证、接口设计、权限实现和现有服务复用范围暂不在本文展开，后续技术设计确定。

验收：无需登录可用测试自定义网关发送任务；登录后账号网关使用服务端权限及配额，超额可见；切换网关时目标清晰，直连网关报错不会伪装成平台限额。

### 3.4 技能与 MCP（P0）

- 技能仅管理本地配置：展示名称、描述、来源目录和启用状态，支持查看内容、搜索、导入和启停；任务中选择可用技能。本地技能脚本按运行时隔离策略执行。
- MCP 列表展示名称、来源、连接状态、提供的工具和错误；用户可新增、编辑、删除个人 MCP 配置，支持本地进程和远程 HTTP 类型，配置项与鉴权方式以实际适配为准。连接测试显示成功或失败原因，不显示密钥。
- 用户可按任务启用可用 MCP；调用时展示服务、工具和状态。具有外部写入、发送或不可判断副作用的调用，在执行前展示目标与参数并请求确认；超时或拒绝时本次调用不执行。
- 技能、MCP 配置和启用状态仅保存在本机，MVP 不提供服务端分发或组织策略；MCP 密钥存系统安全存储，配置导出和日志不包含密钥。
- 本地技能脚本和 MCP 进程拥有的实际权限必须明确告知；对高风险操作的确认只是交互控制，不等于操作系统沙箱。

验收：启用一个测试技能后能在任务中调用；配置测试 MCP 后能查看工具并完成一次只读调用；拒绝写操作后目标未改变；连接失败时能查看可读错误。

### 3.5 定时任务（P0）

MVP 仅支持本机创建、调度和执行；不支持云端计划。任务可使用本机项目文件、用户已启用的本地技能和已配置的 MCP，实际访问范围受沙箱及工具权限约束。模型请求可按任务选择账号网关或自定义网关。

- 创建和编辑名称、提示词、项目、模型及网关、技能/MCP、每天/每周/自定义 Cron、时区和启停状态；显示下一次计划时间，默认使用系统时区并允许修改。
- 仅应用或其明确运行的后台进程在线且设备具备目录与网关权限时执行；关机、休眠或应用完全退出期间不保证触发。恢复后记录错过，不自动补跑，可手动执行。
- 支持暂停、恢复、删除、立即执行及查看历史；显示计划时间、实际开始/结束、状态、错误和关联成果。上次运行尚未结束时跳过本次并记录；删除计划不自动停止正在运行的任务。
- 需要确认且用户无法交互时保持等待，不执行待确认操作；等待时限由实现明确配置并显示。

验收：创建本机计划并观察触发与成果；退出应用错过触发后有记录且不自动补跑；模型不可用、目录权限失效和重复触发均有记录。

### 3.6 系统设置（P0）

- 外观：跟随系统（默认）、Light、Dark；更改即时生效并持久化，系统主题变化时跟随系统项同步变化。
- 语言：跟随系统（默认）、简体中文、English；系统语言不支持时回退英文，切换后主要界面立即更新，保持当前任务和输入草稿。
- 账号：服务地址、当前账号、连接状态、登出。
- 数据：显示本地数据目录，支持在系统中打开；提供清理缓存入口并说明不删除项目源文件或历史记录。
- 所有新增用户可见文字进入中英文词条，时间、日期按语言和所选时区显示。

验收：切换主题和语言后重启保持选择；选择跟随系统时响应系统变化；登出不会删除本地文件。

## 4. 关键非功能要求

- 稳定性：模型连接失败、工具失败、停止、应用重启都有可见状态；本地不可恢复的运行显示中断，不自动重放有副作用操作。
- 访问控制：项目目录授权范围清晰；发送邮件、外部写入和覆盖文件显示明确操作内容。密钥不写普通日志。
- 隐私：默认不把整个本地目录上传；向模型或服务端发送的附件、提取文本和工具结果遵循实际任务授权与平台策略，并在产品中说明。
- 桌面体验：正常分辨率下可使用键盘完成发送、停止、切换任务和关闭预览；状态与错误不能仅靠颜色表达。
- 兼容与分发：仅 Apple Silicon arm64，最低目标为 macOS 13，参考 skillkit 的 Electron Builder DMG/ZIP 与 GitHub Releases。skillkit 使用 macOS 14 CI runner，未显式设置应用最低版本；实际支持范围取决于 Electron 等依赖并需验证。Apple 开发者签名及公证暂不考虑。
- 日志：保留任务 ID、时间、阶段和错误类别；默认不记录附件原文、密钥和完整提示词。

## 5. 核心数据与执行方案

Project（项目、目录授权）→ Task（对话任务）→ Run（每次执行）→ Artifact（成果引用）；Schedule（计划）关联 Project 和任务模板。分别持久化项目元数据、会话索引、运行状态、技能/MCP 配置和计划记录。

- 本地执行由客户端宿主负责目录、文件和进程；piwork 负责身份、模型权限、额度和可用的云端服务。
- 任务历史同步（P0，登录后）：同步任务标题、用户与助手最终文本、创建/更新时间和运行终态；同步后用户可在 Web 打开同一任务并继续对话，由服务端创建新的运行。设置中可关闭同步，不同步凭据、技能/MCP 配置、本地路径或工具参数/输出。
- 本地文件与成果默认不上传；服务端不能访问桌面目录。本地任务需要文件上下文时，用户可明确选择并上传所需文件，或者在 Web 重新添加；未上传资料及本地技能/MCP 不可用于 Web 续接，界面应提示。服务端按其自身模型权限和执行环境运行；不会接管本地进行中的进程。
- 同步以任务 ID 和消息 ID 去重，本地先保存、离线排队、联网登录后重试。MVP 同一任务同一时刻仅允许一个端执行；另一端应显示运行状态并等待完成。断线或状态不明时先刷新服务端状态，不能自动重复执行。Web 续接的新消息需同步回桌面供查看和继续；同步冲突保留数据并提示处理，不静默覆盖。具体认证、接口、版本控制和存储策略留待后续设计。
- 本机隔离后续以 [Pi 官方 Gondolin 方案](https://pi.dev/docs/latest/containerization)为参考；打包、挂载、网络和 MCP 隔离兼容性留待后续考虑，不作为当前已实现或已验证能力。桌面权限提示应如实说明执行环境，不得将 MCP 或扩展描述为已受到 Gondolin 保护。
- Pi Coding Agent 与 Pi Durable 先进行针对文档生成及等待确认两条流程的技术验证；MVP 选定一种主引擎，持久会话和崩溃后安全恢复分别验收。Durable 的恢复不意味着外部副作用恰好执行一次。
- 桌面应用独立仓库；客户端复用经过提取的协议和适配能力，不直接依赖 piwork 的 Next.js 服务端内部模块。Web 的认证、网关及同步接口设计暂不在本需求阶段展开。

## 6. 设计与视觉规范

以 piwork Web 为视觉基准，复用其品牌标识、字号层级、间距、组件形态和浅/深色语义色；参考 `app/globals.css`、聊天侧栏、输入框与成果面板实现。浅色以浅灰画布、白色表面、深色文字、细边框和适量蓝色操作提示为基准；深色使用 Web 对应主题变量。系统字体优先与 Web 一致，中文使用系统中文字体。

交互参考 piwork 的会话、项目、技能和定时任务；借鉴 pi-gui 的多任务状态、可收起工作区和文件预览。pi-pocket 的任务状态及恢复设计可作为技术参考；其扩展兼容性和持久化行为不能直接视为本产品现成能力。

页面状态需覆盖：首次使用、空项目、加载中、权限受限、网络断开、任务执行中、等待确认、失败、空结果和不支持预览。动画克制，不阻挡阅读；本地路径和执行位置应清晰可见。

## 8. 交付与验收

1. **验证阶段**：完成自定义网关、本地文件授权、Office 基础预览和 Pi 引擎候选测试，验证一个 Markdown 生成任务和一个等待确认的任务；输出可行性与风险结论。
2. **开发阶段**：完成第 3 节 P0 需求，并支持已同步任务在 Web 继续处理；相关接口设计另行安排。
3. **联调阶段**：覆盖首次登录、模型无权限、项目迁移、附件处理、预览失败、技能/MCP 调用、本机定时任务、断网/重启、主题语言切换。
4. **发布门槛**：P0 验收全部通过；对有副作用操作的中断与重试进行专门测试；安装、升级、重启以及数据保留在目标 macOS 环境完成验证。

## 9. 实施说明

- 首发面向 macOS 13 及以上的 Apple Silicon，目标范围仍需实机验证；签名与公证暂不考虑。
- 账号设备认证、模型代理和历史同步接口与权限方案暂不展开，产品侧保留对应功能需求。
- Gondolin 打包和权限隔离的兼容性后续再考虑；当前不宣称已经提供相应隔离保障。
- Office 预览以基本验收为准：DOCX 能显示中文段落、表格和图片；XLSX 能切换工作表并查看中文和单元格值；PPTX 能逐页查看中文和图片。损坏或不支持文件须有提示并可用系统应用打开。
- 已同步任务可在 Web 继续工作；本地资料需用户选择上传或重新添加，定时任务仍仅在本机调度。
