# piwork Desktop 设计规范

- 版本：V0.1
- 日期：2026-11-03
- 适用范围：macOS 桌面客户端 MVP，覆盖产品界面与交互；功能范围以 [MVP 需求文档](mvp-prd.md) 为准。
- 规范状态：客户端首版设计基线，数值为设计目标，实际实现时通过样机验证微调。

## 1. 设计定位

piwork Desktop 是 piwork 的桌面版本，面向办公任务；功能、命名和交互以 piwork Web 为主要参照，结合本地文件夹和桌面窗口能力进行适配。界面围绕「提出任务、观察过程、检查成果、继续修改」展开，让用户始终知道当前任务、执行状态和文件位置。

视觉主体继承 piwork Web 的中性灰阶、蓝色交互与轻边框；桌面窗口和高密度操作借鉴 skillkit 的原生窗口处理、胶囊切换与设置导航。两者冲突时以 piwork Web 的品牌和颜色为主：深色使用中性黑灰，不直接沿用 skillkit 的暖棕背景或橙色品牌层。

设计原则：

1. **内容优先**：对话和成果是视觉主角，导航、边框、工具状态退居其次。
2. **状态清晰**：执行中、等待确认、失败及完成必须有文字，颜色和图标只作辅助。
3. **桌面顺手**：键盘可操作，三栏可调整，正确避让 macOS 窗口控制区。
4. **克制一致**：使用中性表面和细线划分层级，蓝色用于链接、焦点和关键交互。
5. **文件可信**：明显标识文件名称、位置、来源和是否已同步，预览不伪装成编辑器。

## 2. 应用框架

### 2.1 主窗口

- 默认三栏：左侧导航与任务、中间任务会话、右侧文件与成果；右栏可关闭、调整宽度，左栏可收起。
- 初始参考宽度：左栏 240 px，中栏自适应且不低于 420 px，右栏 400 px；分隔条提供可见 hover 和键盘调整能力。尺寸是设计目标，不绑定已有 Web 实现。
- 空间不足时优先保留中栏：右栏切换为覆盖面板，左栏收起；不压缩文本到难以阅读。窗口最小尺寸由原型验证确定。
- 标题栏约 56–60 px，避让 macOS 左上角交通灯；标题栏空白区可拖动，按钮、输入框、Tab 和分隔条不可拖动。
- 各栏独立滚动；对话输入框固定在对话区底部。切换任务时保留草稿；预览关闭或调整宽度不清空任务内容。

```text
┌─────────────────────────────────────────────────────────────────┐
│ ● ● ●    piwork                                   账号 / 设置   │
├──────────────┬───────────────────────────┬──────────────────────┤
│ 新对话       │ 任务标题        模型 · 状态 │ 文件名         关闭 │
│ 项目         │                           │ 文件来源 / 路径      │
│ 项目会话     │ 对话、工具状态与结果       │                      │
│ 最近对话     │                           │ 文档 / 表格 / 图片   │
│ 最近任务     │                           │                      │
│              │ 附件 · 输入 · 发送        │ 打开 · 另存为       │
└──────────────┴───────────────────────────┴──────────────────────┘
```

### 2.2 导航与页面层级

左栏对齐 piwork Web，依次呈现「新对话 → 我的文档 → 定时任务 → 技能 → MCP → 项目 → 最近对话」，设置位于底部，顶部提供搜索和侧栏收起。MCP 是桌面端保留入口；“我的文档”为应用文档库（`userData/library` 下的真实文件夹与文件），界面与功能对齐 Web 版 `/documents`：分类 tab、网格/列表、上传/拖拽、笔记与文件夹、重命名/移动/导出/删除、AI 生成标记，并接入桌面富预览面板。当前任务与页面用浅灰底、文字字重和可选的左侧指示共同标识。默认不以强反色填充整个导航行。

项目、技能、MCP 和计划页采用列表或表格为主，顶部提供标题、简短说明和主要操作；设置使用左侧分类导航与右侧内容。参考 skillkit 设置页的透明导轨、细分隔线和低强调选中态。

## 3. 设计 token

所有颜色通过语义 token 引用；组件不直接绑定色值。以下基线取自 piwork `app/globals.css` 的全局 light/dark 值；Web 中针对聊天页面的局部覆盖仅作为组件参考。客户端可以在无障碍测试后调整对应语义值。

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#fafafa` | `#000000` | 主画布 |
| `canvas-soft` | `#f2f2f2` | `#111111` | 侧栏、次级区域 |
| `surface` | `#ffffff` | `#0a0a0a` | 卡片、输入、弹窗 |
| `surface-hover` | `#f2f2f2` | `#1a1a1a` | hover / 低强调选中 |
| `border` | `#ebebeb` | `#262626` | 分割与普通边框 |
| `border-strong` | `#e0e0e0` | `#333333` | 输入和可交互边框 |
| `text-primary` | `#171717` | `#ededed` | 标题、主要文字 |
| `text-secondary` | `#4d4d4d` | `#a1a1a1` | 描述、次级文字 |
| `text-muted` | `#8f8f8f` | `#6e6e6e` | 辅助信息，需验证对比度 |
| `action` | `#171717` | `#ededed` | 主要按钮 |
| `action-text` | `#ffffff` | `#171717` | 主要按钮文字 |
| `link` / `focus` | `#0070f3` | `#3291ff` | 链接、键盘焦点 |
| `warning` | `#f5a623` | `#f5a623` | 等待、警示图标与边框 |
| `danger` | `#ee0000` | `#f31b1b` | 错误、危险操作 |

成功状态采用低饱和绿色配文字，具体前景/背景须通过对比度验证。状态色不能仅靠颜色传达。弱化文字 token 不用于必要说明、表单标签和小字号正文，避免低对比度。

### 主题规则

- 设置支持跟随系统（默认）、Light、Dark；跟随系统时系统外观变化立即同步。
- 浅色使用不透明表面与发丝边框，避免奶油底、暖色大面积渐变和毛玻璃。
- 深色使用中性黑灰、浅色文字和轻边框；保持办公内容阅读舒适，不复用 skillkit 默认暖棕色。
- 不使用橙色作为主按钮或大面积品牌色；橙黄仅用于警告。彩色渐变仅可用于经审查的空状态插图，不能用于工作内容背景。

## 4. 字体、间距与层级

### 字体

- 界面优先 Geist / 系统无衬线；中文依次使用 PingFang SC、系统 sans-serif。字体不可用时平滑回退。
- 正文默认 14 px / 20–22 px；对话长文可用 15–16 px / 1.6；次级文字 12–13 px / 18 px，不能以过小字号承载重要操作说明。
- 页面标题 20 px / 28 px，字重 600；区域标题 16 px / 24 px，字重 600；标签 13–14 px，字重 500；正文 400。
- 代码、路径和日志使用系统等宽字体；长路径中间省略，hover 或详情可查看完整路径并复制。

### 尺度

- 基础间距：4、8、12、16、24、32 px；页面内边距建议 24 px，紧凑工具栏 12–16 px。
- 标准交互高度 36 px；输入框和主要操作 40 px；图标按钮可视尺寸 32–36 px，点击区域至少 36 × 36 px。图标建议 16–18 px。
- 圆角：小型控件 6 px、输入框 8–12 px、卡片/弹窗 12–16 px；模型选择和分段切换可采用胶囊形。
- 边框优先于阴影；常规卡片不使用明显投影。菜单、弹窗可用轻投影表示浮层。
- 动画参考 150–200 ms，侧栏过渡不超过 300 ms；遵循系统减少动态效果设置，不因动画延迟关键状态。

## 5. 通用组件

### 按钮和选择

- 每个区域仅一个最主要操作；主按钮浅色近黑底白字、深色浅色底深字。次按钮透明或表面底加边框；危险操作用明确文字和危险色。
- hover、active、disabled、loading、focus-visible 必须可区分；异步提交时按钮可显示进度并防止重复提交。
- 分段切换与紧凑 Tab 采用 skillkit 的胶囊语言；强反色只用于真正的模式切换，设置和侧栏导航使用柔和底。
- 纯图标按钮必须提供可访问名称与悬停提示；键盘焦点使用清晰的蓝色轮廓。

### 输入与反馈

- 输入框由标签、控件、帮助或错误信息组成；禁止仅用 placeholder 作为标签。字段错误展示原因和修复方法。
- 搜索支持清空、空结果和加载状态；列表操作的结果用简短提示，长任务状态保留在任务中。
- 确认弹窗说明操作对象与结果；危险操作按钮明确写「删除任务」「覆盖文件」等，避免模糊的「确定」。
- 弹窗打开时焦点进入弹窗、关闭后返回触发点；Esc 可关闭非阻塞弹窗，执行中的审批按具体状态处理。

### 列表、标签和菜单

- 列表行呈现名称、必要元数据、状态和就近操作；鼠标悬停才出现的操作对键盘焦点同样可见。
- 标签只用于状态、来源或分类，避免以多色标签制造视觉噪声。长列表支持滚动与空状态。
- 列表选中态浅灰底、主要文字和字重共同表达；菜单与弹窗保持一致的危险操作位置和样式。

## 6. MVP 页面细则

### 6.1 会话与执行过程

- 会话顶部展示任务名、项目/目录、模型或网关和状态；任务执行位置清楚可见。
- 用户消息与助手消息通过对齐、间距和轻背景区分；助手长文支持 Markdown、代码块及可复制内容。
- 工具调用默认显示名称、运行状态、耗时与展开入口，详细参数和输出默认折叠。状态至少包括执行中、等待确认、完成、失败、已停止；不能只显示旋转图标。
- 输入框支持多行、附件、技能选择、模型/网关选择、发送和停止；右下角放模型选择（当前只有一个自定义模型及配置入口），左侧“＋”菜单提供文件、技能和 MCP 入口，已选能力以标签显示。附件以名称、类型、状态及移除操作展示。输入过程中切换视图不得丢失草稿。
- 任务运行中发送行为与停止行为清楚区分；断网、同步中、历史冲突和运行状态不明均给出说明和可执行动作。

### 6.2 文件与成果预览

- 右栏头部展示文件名、格式、来源和可展开的完整路径；提供关闭、系统打开、定位和另存为。
- 文本、Markdown、图片、PDF、DOCX、XLSX、PPTX 均为只读预览；用页码或工作表切换控件说明当前位置。
- 显示加载、空文件、过大、格式不支持、文件不存在及预览失败状态；保留系统打开入口。Office 预览允许基础格式偏差，必要时提示以原应用为准。
- 附件、本地产出和已上传到服务端的资料使用不同来源标签；本地文件不会因同步会话而被暗示已上传。

### 6.3 项目空间

- 首页呈现项目名称、目录、最近任务和访问状态；创建项目时通过系统目录选择器选取文件夹。
- 缺失目录、无权限或重复目录给出明确修复入口。移除项目时说明保留本地文件。
- 文件列表对长名称省略展示但支持完整查看；文件、文件夹使用一致图标，不能仅用颜色区分。

### 6.4 技能与 MCP

- 支持列表搜索、查看、启用/停用；显示名称、来源、状态和最近连接/错误信息。
- MCP 配置表单区分服务名称、类型、地址或命令、认证；密钥默认遮蔽，测试连接提供明确反馈。
- 启动外部进程和执行写入操作的确认界面说明对象和用途；当前不宣称已提供未验证的沙箱隔离。

### 6.5 定时任务

- 列表显示任务名称、周期、时区、下次运行时间、最近结果和启停状态；详情展示运行历史及失败原因。
- 创建表单按「任务内容 → 项目与能力 → 计划 → 确认」组织，明确标注本机执行和应用退出/休眠后的错过规则。
- 暂停与删除分别说明影响；任务执行中需要人工处理时保持清晰的等待状态。

### 6.6 设置与登录

- 设置分类：外观、语言、账号与连接、模型网关、数据。跟随系统是主题及语言默认选项，选择后即时生效。
- 支持账号网关和自定义网关的独立配置，界面清楚展示当前使用的服务地址、模型来源及连接状态；密钥不以明文回显。
- 未登录可访问本地项目和自定义网关；登录状态、额度不足和服务不可用需清晰区分。

## 7. 可访问性与质量门槛

- 正文与背景对比度目标至少 4.5:1，大号文字至少 3:1；交互图标和焦点指示目标至少 3:1。对照明暗主题实际配色检查，必要时调整 token。
- 任务导航、输入、发送、停止、预览、设置均能通过键盘完成；焦点顺序符合视觉顺序，焦点不能被滚动容器或弹窗遮挡。
- 组件有语义名称，加载、成功、失败和等待审批通过文本或辅助技术通知；不自动把流式内容的每个字符都播报。
- 截图验收至少覆盖浅/深主题、中文/英文、三栏/窄窗、登录/未登录，以及加载、失败和空状态。
- 实际样机验证桌面交通灯、滚动、面板缩放、字体回退、长路径、中文表格和图片预览。产品开发以可用行为为准，不以静态稿代替交互验证。
